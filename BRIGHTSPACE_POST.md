# Professional Portfolio

The goal of this portfolio is to create one clean GitHub repository that you can later share with an employer or use when applying for an internship. It is not a new programming assignment. You are organizing and presenting work you have already completed in this course.

## What to Include

Your repository should have:

1. A clear main `README.md` that introduces you, summarizes your technical skills, and highlights three projects.
2. One early-course C program that shows your starting point.
3. One mid-course C program that shows growth in areas such as functions, arrays, pointers, structures, or file processing.
4. Your final BroBank project.
5. A short `README.md` inside each project folder explaining:
   - what the program does;
   - the skills it demonstrates;
   - how to compile and run it; and
   - one design choice, test, or bug you fixed.
6. Optional diagrams or screenshots if they make your work easier to understand.

## Keep It Simple

You do not need to create a new program or rewrite BroBank. Use your own completed work and present it professionally. A recruiter should be able to open the repository, understand your projects quickly, and follow your instructions to run them.

Before submitting, remove compiled files, passwords, API keys, and unnecessary personal information. Credit any permitted assistance or tools according to the course policy.

## Submit on Brightspace

Submit the link to your GitHub portfolio repository on Brightspace. Before submitting, open the link in a private/incognito browser window to confirm that it is accessible and that all links work.

You may use the provided sample structure as a guide, but the descriptions and reflections must be your own.
