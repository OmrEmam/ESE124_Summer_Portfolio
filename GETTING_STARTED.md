# Create Your Professional Portfolio

This template helps you organize C programs you have already completed. You do not need to write a new program or rewrite BroBank.

## Recommended: Create Your Own Repository

1. Open the `professional-portfolio-template` repository on GitHub.
2. Select **Use this template**, then **Create a new repository**.
3. Name the new repository something professional, such as `c-programming-portfolio`.
4. Choose **Public** only if you are comfortable sharing the contents with employers.
5. Create the repository and edit the files in your new copy—not in the class template.

This makes a clean repository without copying the template’s commit history. No Git merge is required.

## Add Your Work

1. Edit the main `README.md` and replace every bracketed prompt.
2. Copy one of your own early-course programs into `01-early-program/`.
3. Copy one of your own mid-course programs into `02-midcourse-program/`.
4. Copy your own completed BroBank files into `03-brobank/`.
5. Update the `README.md` inside each project folder.
6. Add an optional diagram or screenshot to `diagrams/` if it helps explain your work.
7. Remove any placeholder or `.gitkeep` files that are no longer needed.

## If You Already Created a Portfolio Repository

Do not merge another student’s repository into yours. Add the template files to your existing repository while preserving your own code:

1. Download this template using **Code → Download ZIP**.
2. Copy the main `README.md` and the project-folder README files into your repository.
3. Keep your own source files and project history.
4. Edit the copied instructions to describe your own work.
5. Review the changes before committing them.

If a filename already exists, compare the two files and copy only the useful structure. Do not overwrite your completed work without keeping a backup.

## Final Check

- Open every link and confirm it works.
- Follow your own compile and run commands from a fresh copy.
- Remove executables, object files, passwords, API keys, and unnecessary personal information such as a student ID.
- Proofread the writing for an audience that has not taken this course.
- Credit permitted assistance and tools according to the course policy.
- Open the repository in a private/incognito browser window to confirm that your instructor can access it.

Submit the URL of your own portfolio repository on Brightspace.
